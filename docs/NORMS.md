## 1. 通用认知规则（跨项目 · G）

下列约束思考与表述。每条：**规则** + **为什么**（简短）。

| ID | 规则 | 为什么 |
|----|------|--------|
| **G1** | **完整优先于炫短。** 对主人说明、HANDOFF、log、任务书用完整句写清条件、边界与结论。一秒能确认的事可以短答。 | 刻意压短易省掉限定，跨会话与落盘会歧义。 |
| **G2** | **优先直接陈述。** 少用「不是…而是…」「是…不是…」当主结构。纠正误解用从属短句，不先立假靶。 | 对仗句架易发明虚假对立、削弱诚实。 |
| **G3** | **规则与原因一起给。** 写规则附一句「为什么」；读规则先理解原因再应用。原因写在「为什么」列或另段，**不把原因嵌进命令动词里冒充规则**。 | 只背规则会在边界机械执行或忽略；知道原因才能判断是否仍适用。 |
| **G4** | **正反例子优于纯禁止。** 对反复踩坑的规则配反面 + 正面各一例（见 §4）。 | 抽象禁止约束力弱；可见坏例子更能锚定行为。 |
| **G5** | **语气分档。** 必须/禁止 · 可推翻倾向 · 草案/未证实。未证实不得写成 FIXED 或「用户已可用」。 | 混用语气会误判可靠性。 |
| **G6** | **AI 落盘用完整句；人可用口语。** 理解后写成可归档句子。 | log 与交接须可独立阅读。 |
| **G7** | **技术文档避免假绝对。** 分析结论标明证据范围与分档（静态对照 / 单号样本 / 假说 / 已证伪）；欢迎后续用源码与真机纠正。禁止用「必然」「永远」「一定就是」等语气把未穷尽结论写成不可质疑的真理。 | 写得太绝对时，后继 AI 即使看到矛盾也怕推翻文档，错误会长期固化。完整约定见 [TECH_DOC_CONVENTION](./tech/TECH_DOC_CONVENTION.md) §1.10。 |

#### G12 交接细则（禁止用短表代替本段）

1. **角色：** `docs/HANDOFF.md` 是**唯一完整现状入口**。TASKBOARD 与任何「一句话状态」只作导航，不得替代 HANDOFF 正文。  
2. **失真声明：** 文首显著位置写明 AI 维护、可能出错；**证据优先级**：当前源码与真机与 `RustMadoka_data/wire/`（若有）＞ 本 HANDOFF ＞ 过时 PLAN/历史 log。矛盾时修订文档并写 `docs/logs/`（G7）。  
3. **篇幅纪律（G10）：** 本会话变更、未完成条件、下一动作：**只许更详不许更少**。禁止「一句话收束本会话」（G8）。  
4. **结构最低要求（可增不可删语义）：**  
   - 摘要：产品是什么、交付物、端口、本阶段已落地（标 **CODE / CLI 验证**，禁止无点测写 FIXED）  
   - 明确尚未完成（完整条件）  
   - 协作授权当前值  
   - 本会话变更全文或链到当次 log 的完整条件段落  
   - 运行/构建命令  
   - 下一会话默认动作与硬阻塞  
   - 规范速查与近期 log 索引  
   - 修订表：真墙钟到**分钟**  
5. **开机检查（后继会话必须按序）：** 读 HANDOFF 第 0 节与本会话变更 → NORMS（含本条）→ OWNER 需求/原文冲突时打开 RAW → TASK_REMAINING_FULL → 当轮 PLAN/tech → 核对 `crates/` 与根目录双 exe。  
6. **完成等级用语：** CLI/单测/wire 成功 → 只写「CODE」或「CLI 已验证」；**无主人点测不得写 FIXED / 用户已可用**（P5）。  
7. **对主人部分白话**（G11）：下一动作与风险写清「点哪里、会看到什么」。  
8. **实质工作收口：** 写 `docs/logs/日期-主题.md`，并更新 HANDOFF **至少 3 行**有意义内容（P6）。  
9. **归档纪律：** 过时技术文档**移入** `archive/` 并写 README，**禁止默默删除**有对照价值的历史说明（与清理大体积沙箱区分：沙箱/旧 exe 可删，历史 tech 归档）。

#### 2.4.1 为什么本地明文（主人钉死 · 完整）

1. **不考虑**黑客攻击、本机数据泄露类威胁模型；这些游戏账号材料**不值钱**。电脑上通常有更有价值的东西，不值得为 token/引继 **浪费资源与精力**，更不值得给 **CLI/自动化测试** 加解密障碍。  
2. **会用 CLI 的朋友默认懂技术，自行负责。** 母项目甚至明文存储密码等；本 fork **没有必要**做比母项目更麻烦的本地防护。  
3. **跨端一致：** Win / macOS / Arch / OpenWrt **全部永远允许明文**；不得在某一端「默认强制加密」。  
4. **家用（P9c）：** 唯一额外点是小孩打不开加密组、看不到组内密码；**不要**为了没有实用价值的安全牺牲「同卡同登录」等便利。

## 5. 不做（规则清单 · 无缘由嵌套）

- 把本机引继/密码/token **推到**远程仓库或公开文档。  
- 把用户 data / 账号材料 **打进**分发给朋友的 exe 或安装包。  
- 默认团战多开农场。  
- 完整游戏包打进客户端或公开仓。  
- 为本项目把旧 Python 装进系统 PATH。  
- 实质任务不写 log。  
- 无注释、无文档对照的大块产品逻辑。  
- 开关 false 时擅自杀进程。  
- **正式自用后**擅自清空/移走含真号的 `RustMadoka_data`（P1b）。  
- **默认**推进 token 再加密 / 本地防读盘军备（P9b）。  
- 以「审计还有未做项」把本机加固默认排主线。  
- 无证据写 FIXED /「用户已可用」。  
- 在 Win/macOS/Arch/OpenWrt 任一端要求「必须加密才算安全完成」。
