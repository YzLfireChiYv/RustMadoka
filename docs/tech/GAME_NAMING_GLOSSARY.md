## 0. 词源分层 + 重构优先级

| 层 | 是什么 | 重构优先级 |
|----|--------|------------|
| **Fnc** | **功能身份**（玩法规则、状态机） | **最高** |
| **D** | 协议 path / mst id / 请求体字段 | **最高**（和 Fnc 绑定） |
| **E** | 工具中文（魔女召唤…） | 中：只当别名索引 |
| **F** | 玩家习惯（主线、jjc、舔盒） | 中：别名索引，标非官方 |
| **A/B/C** | 客户端 UI 日/英/**繁中** | 低～中：文案与截图对照用，可后补 |

**禁止：** 把 E/F 当成官方功能名写进设计真理。  
**允许：** 文档与代码注释用「功能身份 + key + 主 path」指称，括号里再写 E/F 别名。

## 1. 功能身份表（主人机制 · 优先阅读）

### 1.1 链接 Raid / multi_raid（工具侧拆成四个中文名）

| 项 | 内容 |
|----|------|
| **功能身份** | **同一套限时 Raid 玩法**（协议域 **`multi_raid`**；攻略常称リンクレイド）。工具中文「魔女召唤 / 援助 / 舔盒 / 点赞」都是**这一个功能下的操作切片**，不是四个无关玩法 |
| **开放** | **限时**；每期 **20 个等级** |
| **新一期** | id **可能新**，也可能是**以前开过**的同一内容再开 |
| **进度** | 以前开过 → **继承**上次进度；否则须从**低难度重新通关**解锁 |
| **通关后** | 平时可**自选难度开房间** |
| **房间** | 他人可加入；多种模式；可限制**仅自己**或**仅工会**等 |
| **工具·魔女召唤 `self_raid`** | **自己开房打**；默认**本期最高已解锁难度**，**不用填关卡等级** |
| **工具·魔女援助 `support_raid`** | 打**配置里填写的等级**；可**只选自己工会的房间/关卡** |
| **工具·魔女舔盒 `raid_reward`** | 领奖/结算类（「舔盒」=F/E 黑话） |
| **工具·魔女点赞 `like_raid`** | 点赞类操作（细节待补 API） |
| **队伍约束** | 一人**一个队伍**上场；**可以朋友帮忙**进房（与总力战对比见下） |
| **协议钩子（已见代码，未穷尽）** | mst：`get_multi_raid_mst_list` · `get_multi_raid_stage_mst_list` 等；运行：`get_top` / `get_multi_raid_info` · `initialize_stage` · `add_damage` · `finalize_stage_for_user` · `receive_reward` · `get_multi_raid_stage_data_list` · `recover_stamina` 等（以 `daily.rs` / requests.py 为准，版本会变） |
| **待补** | 「点赞」精确 API；工会过滤字段；20 级与 stageMstId 映射 |

### 1.2 总力战 / solo_raid · 与「灯塔危机」

| 项 | 内容 |
|----|------|
| **功能身份（确定）** | 原版 automadoka **已有**日常模块 **`solo_raid`**，工具中文名 **「扫荡总力战」**（`@name` / 目录表，与「有没有这功能」无关——**有**）。协议域 **`solo_raid`**。Rust 现有 `solo_raid` 实现路径（扫荡类请求，细节以源码为准） |
| **和灯塔危机的关系（主人说明）** | 这套玩法 **与「灯塔危机」相关**；「灯塔危机」是游戏侧说法，「扫荡总力战」是 **工具中文名（E）** |
| **玩法要点（主人说明）** | 玩家可用**自己的多个队伍接力**打 |
| **对比 multi_raid** | Raid：一人一队上场，朋友可进房帮忙。本模式：仅用自己的多个队伍接力 |
| **协议（工具已对接的一类）** | 例如 `get_solo_raid_mst_list` · `/api/solo_raid/get_top` · `skip_quest_battle` 等（以 requests.py / daily.rs 为准） |
| **仅显示名层可后补** | 繁中/日文客户端按钮是否就写「灯塔危机」三字——不影响「原版有扫荡总力战、key=solo_raid」这一事实 |

## 4. 重构时「名字」怎么用（主人意图）

```text
功能身份（规则/状态机）
    + 协议：读什么 id / 发什么 path+body / 回包用哪些字段
    + 工具 key / 中文别名（可选）
    + 客户端显示名（后补，繁中/日/英）
```

显示名对齐是**体验与文档友好**；**没有显示名也可以写协议与模块**。  
有显示名时填进 A/B/C，方便和截图对上，**不阻塞**协议分析。
